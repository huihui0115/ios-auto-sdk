# 整体代码与易用性审计

Round 73–75 · 2026-09-07 · SDK v1.38.2 / VS Code 0.13.1

本轮按“安装 → Wi-Fi 配对 → 编写 → 执行/停止 → 可视化采集 → 发布”审查主要链路，
同时抽查文件沙盒、HTTP 重定向、WebSocket 鉴权/帧预算和运行时资源限制。
这是有范围的工程审计，不是逐行形式化证明，也不代表所有 iOS 版本/真机均已验收。

不将旧矩阵当作当前版本功能证明。

## 已修复与验证方式

| 问题 | 用户影响 | 修复与回归 |
| --- | --- | --- |
| 定位/VPN 固定等待，不感知脚本/子线程取消 | 点停止后还要等待系统回调 | 共用 50ms 分片等待、单调时钟期限；回调门闩单测 |
| 定位主线程前置查询可能阻塞，初始化晚于超时仍请求授权 | 卡顿或结束后出现迟到定位请求 | 去掉 services preflight，初始化/状态读取后重查有效性；慢工厂回归 |
| 定位错误直接泄露 CoreLocation domain | 错误契约不一致 | 包装 AutoSDKErrorDomain，保留 underlying；拒绝/no-fix 测试 |
| Inspector 旧请求、旧模式结果覆盖新选择/手写代码 | 复制了错误代码 | 选择版本隔离，旧 operationStart 不回滚 ID；执行真实 Webview JS 回归 |
| 空快照残留旧代码、隐藏期间请求不结束 busy | 误插入旧代码或按钮无法恢复 | 清空/禁用复制插入；所有请求配对结束 |
| Bonjour 同步失败/取消遗留资源；满额后无法更新已知 IP | 扫描可靠性降低 | 每个初始化阶段检查完成态；保留已知设备刷新；异常服务容错 |
| 重输 token 时工作区/当前手机已变 | 原设备覆盖新选择 | 恢复前后校验配对目标；异步切换回归 |
| 只有整文件运行；非 .ts 文件的 TypeScript 模式报错 | 小段调试繁琐 | 独立右键 Run Selected Code；空/多选拒绝；按语言模式转译 |
| SPM 未显式链接 sqlite3 | 集成依赖隐式链接行为 | 与 CocoaPods 对齐 |
| 当前安装指南仍含已删除 WDA 激活流程 | 用户照文档无法完成 | 删除过时流程，保留 Git 历史；文档重新生成 |

选区运行是一次新的脚本执行，不是 REPL，不继承先前变量；需要包含所依赖的声明。
定位授权窗口若已由系统显示，取消不会替用户撤回系统授权；取消只关闭当前请求的结果和后续定位路径。

- npm 官方 registry 的生产依赖 audit：本轮报告 0 个已知漏洞。这不等于没有未知漏洞。
- bootstrap 保持 61262 / 61440 UTF-16 码元；不为新增便利操作继续挤占手机运行时预算。
- 验收命令：verify、Node 测试、TypeScript 5.6.3 类型检查、文档生成、插件 check/test；
  原生新增测试只使用假定位管理器，不触发真实 TCC/定位守护进程。

## 尚未解决，按优先级

1. 真机验收：首次 Wi-Fi 添加、token 错误重试、IP 变化、切后台挂起、断网恢复；
   私有触摸/节点/VPN entitlement 的实际可用性。Windows 本机无法替代 iPhone/Xcode 验收。
2. 停止边界：纯 JavaScript 无限循环不能安全抢占；部分旧的 HTTP/适配器等待
   只检查整脚本 stop，子线程 cancel 的一致性仍应专项覆盖，不能承诺所有原生调用都在 50ms 内退出。
3. 工程体验：目前每个工作区选一台手机，缺少持久设备列表、工程依赖打包和资源增量同步。
4. 调试深度：没有持续视频流、JavaScriptCore 断点/变量检查；目前是执行、日志与可视化采集工具。
5. 发布可观测性：Pages 探测失败目前无法区分未启用与权限/网络故障，在线文档可用性须单独验证。

后续应先补真机验收与取消契约，再考虑扩展功能，不用更多 API 名称掩盖上述缺口。
